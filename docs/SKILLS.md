## 3. Conflicts with PLAN.md (flagged)

| Skill                                               | Conflict                                                                                                                    | Resolution                                                                                                                           |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `chequeo-pre-commit`, `revisar-diff`, `plan-rapido` | Written for a time-boxed hackathon team with per-person "roles"; `plan-rapido` waits for an OK before every multi-file task | Don't use them here. `verification-before-completion` + `code-review` cover the same checks; checkpoints follow §0 rule 5.           |
| `ui-ux-pro-max`                                     | Its font-pairing data includes generic faces (Inter, Roboto…) that R4 forbids as the display face                           | Only use it for exploration; R4/§8.2 win. A CI grep for forbidden font names (§13) catches mistakes.                                 |
| `ponytail` vs. the §3 quality stack                 | Ponytail pushes for less tooling; §3 asks for ESLint, Prettier, Vitest, Playwright and Lighthouse CI                        | §0 rule 4 says never cut quality to save code. Tools get added when they have something to check, not all on day one (see ADR-0001). |
